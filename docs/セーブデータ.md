# セーブデータ（ブラウザごとの分離）

セーブデータは**ブラウザごと**に分かれている。同じサイトを開いても、別のブラウザ（Chrome と Safari、別のプロファイル、別の端末）なら、キャラの成長・ゴールド・アイテム・ダンジョンの探索・使い魔・戦闘は、それぞれ別々になる。

## 仕組み

- ブラウザを見分けるのは、サーバーが発行する Cookie **`yamimaho_player`**（ランダムな 64 桁の 16 進トークン。HttpOnly・SameSite=Lax・**400 日**。Secure は `SESSION_SECURE_COOKIE` に従う）
- 初めてアクセスしたブラウザ（Cookie がない・形が不正・DB に無い）には、新しい**ゲスト**（`users` の新しい行。メールは `guest-<uuid>@yamimaho.local`）を作り、Cookie を発行する。ゲストにはキャラ 4 人・初期装備・初期アイテムが用意される
- 以降は、Cookie のトークンのハッシュ（`users.player_token_hash`、sha256）でユーザーを見つけ、そのユーザーのセーブで動く。**DB には生のトークンを保存しない**（DB が漏れても Cookie は作れない）
- ログインのセッション（`laravel-session`）は、セーブの識別には使わない。セッションは 120 分で切れ、古いブラウザには「共有のデモユーザーでログイン済み」のセッションが残っているため。毎リクエスト、Cookie から決める（`Auth::setUser`。実装は `app/Http/Middleware/EnsureDemoPlayer.php`、ゲスト作成は `DemoPlayerService::createGuest`）
- フロント（`api.js`）は何もしなくてよい。`credentials: 'include'` で Cookie が付き、本番は CloudFront の `/api/*`（同一オリジン。`AllViewer` ポリシーが Cookie / Set-Cookie を通す）、開発は Vite のプロキシ経由で同一オリジン
- 管理画面（`/admins`）・テスト戦闘・ショップ・使い魔なども、すべて「そのブラウザのセーブ」を操作する

## 注意（プレイヤーに伝えること）

- **Cookie・サイトデータを消すと、そのブラウザのセーブには戻れない**（新しいセーブになる）。別のブラウザ・別の端末でも同じセーブは使えない。プライベートブラウズ中は、閉じると消える。ホーム画面にも注意書きを出している
- 「ひきつぎコード」（ブラウザ間・端末間の移行）は作っていない。必要になったら、`users` に引き継ぎ用のコードを持たせ、入力した人の Cookie を、そのユーザーのトークンに切り替える形で足せる

## リセット（ホームの「リセット」）

- そのブラウザのセーブ（キャラの成長・ゴールド・アイテム・ダンジョン・使い魔・戦闘）だけを消す。**ほかのブラウザの戦闘やセーブには触れない**（`ResetController` は `battle_states` を `user_id` で絞って消す）

## 他人の戦闘は見られない

- `GET /api/battles/{id}` と `POST /api/battles/{id}/actions` は、**自分の戦闘だけ**。ほかのユーザーの戦闘 ID を指定すると 404（`user_id` が空の戦闘だけは従来どおり）

## 設定（環境変数）

| 名前 | 既定 | 内容 |
|------|------|------|
| `GAME_PER_BROWSER_SAVES` | `true` | `false` にすると、従来どおり**全ブラウザが共有のデモユーザー**を使う。**元に戻したいときのスイッチ**。`phpunit.xml` では `false`（既存のテストはデモユーザーで動く） |
| `GAME_GUEST_CREATE_PER_HOUR` | `300` | 1 時間に新しく作れるゲストの数の**全体の上限**。超えたら新しいブラウザは 429（「混み合っています。しばらくしてからもう一度お試しください。」）。Cookie を持つ既存のブラウザは影響を受けない。`0` で無制限。Cookie を受け付けないクライアントがリクエストのたびにユーザーを作り続けるのを止める歯止め |

## 運用

- マイグレーション `2026_11_09_000001_add_player_token_hash_to_users`（`users.player_token_hash`）が必要。本番コンテナは起動のたびに `migrate --force` を実行するので、デプロイで自動適用される
- **切り替え直後は、全員のセーブが新規スタートになる。** それまでの共有セーブ（デモユーザー `demo@yamimaho.local`）は DB に残るが、誰からも使われない（引き継ぎは作っていない）
- デプロイ後、本番で `curl -i https://<ドメイン>/api/player/navigation` を叩いて、`Set-Cookie: yamimaho_player=…; httponly; samesite=lax; Max-Age=34560000` が返ることを確認する
- ゲストのユーザー行は増え続ける。古いゲストを消すコマンドはまだ無い（本番にはスケジューラが無く、cron の追加が要る）。消すときは、`users` の行に加えて `battle_states`（`nullOnDelete` なので行が残る）と `sessions` も消す。ほかの `user_*` テーブルは `cascadeOnDelete`
