# ダンジョンイベント企画テンプレ

新しい探索イベントを追加するとき、企画側はこのテンプレに沿ってデータを渡してください。実装側は [`dungeon_events.csv`](../backend/database/csv/dungeon_events.csv) と [`dungeon_event_nodes.csv`](../backend/database/csv/dungeon_event_nodes.csv) に落とし込みます。

関連: [ダンジョン探索.md](./ダンジョン探索.md)

---

## 渡し方（3点セット）

| 優先度 | 内容 |
|--------|------|
| 必須 | イベント概要 + ノード表（下記テンプレ） |
| あると良い | mermaid フロー（**node_key 名**付き） |
| 任意 | 参考イベント（「宝箱に近い」など） |

Markdown 1ファイルにまとめて Issue / チャットで渡してもらえれば、実装・テストまで進めやすいです。最初から CSV 直書きより、表形式の方がレビューしやすいです。

---

## 1. イベント概要（1枚テンプレ）

```markdown
## イベント名（日本語）
- code: snake_case（例: trap_arrow）
- floor: 1
- weight: 10（1層の合計100以内。他イベントと調整）
- event_type: 分類ラベル（実装参照用。例: party_choice_stat_check）
- start_node: intro（最初の node_key）

## 概要（1〜2行）
プレイヤーが何を体験するイベントか

## 分岐の要約
- 成功時: ...
- 失敗時: ...
- 特殊: 全滅 / 戦闘突入 / アイテム入手 など
```

**weight:** 1層の探索イベント weight 合計は **100** が目安です。新規追加時は既存 weight の再配分が必要になることが多いです。

## 2. ノード一覧（メイン）

各ステップを **1行 = 1ノード** で書いてください。

### コピペ用テーブル

| node_key | type | 表示テキスト / 内容 | 話者 | pc1 | pc2 | pc3 | pc4 | 判定/効果 | 成功→ | 失敗→ | 次→ |
|----------|------|---------------------|------|-----|-----|-----|-----|-----------|-------|-------|-----|
| intro | narration | 〇〇が起きた！{target_name}が… | — | | | | | | | | react |
| react | dialogue | （セリフ） | random_ally | イルミ台詞 | ヨウ台詞 | ユメノスケ台詞 | ヒルユキ台詞 | | | | roll |
| roll | stat_check | （表示なし） | — | | | | | spd ×3 | success | fail | |
| end | end | — | — | | | | | | | | |

### 列 → CSV 列の対応

| 渡す列 | CSV 列 |
|--------|--------|
| node_key | `node_key` |
| type | `node_type` |
| 表示テキスト | `text`（改行は `\n`） |
| 話者 | `speaker_role` |
| pc1〜pc4 | `dialogue_pc1`〜`dialogue_pc4` |
| 判定/効果 | `stat_attr` / `stat_multiplier` / `fixed_damage` など |
| 成功→ / 失敗→ / 次→ | `next_on_success` / `next_on_fail` / `next_default` |

### キャラ列（固定）

| 列 | キャラ | スロット |
|----|--------|----------|
| pc1 | イルミ | pc1 |
| pc2 | ヨウ | pc2 |
| pc3 | ユメノスケ | pc3 |
| pc4 | ヒルユキ | pc4 |

## 3. node_type 早見表

実装: [`DungeonExplorationEngine.php`](../backend/app/Services/Dungeon/Exploration/DungeonExplorationEngine.php)

| type | 用途 | 渡すときに書くこと |
|------|------|-------------------|
| `narration` | 地の文 | `text` のみ |
| `dialogue` | セリフ | `speaker_role` + pc1〜4 の台詞 |
| `stat_check` | 能力判定 | `stat_attr`（str/spd/know/mag/def/spirit/vit）+ `stat_multiplier` + 成功/失敗先 |
| `party_choice` | 「誰がやる？」選択 | `text`（プロンプト）+ 次ノード |
| `party_choice_skip` | 選択 + スキップ肢 | スキップ文言は **pc4 列**（例: 「毒見しない」） |
| `binary_choice` | はい/いいえ | pc1=はいラベル, pc2=いいえラベル |
| `chance_branch` | 固定確率分岐 | `stat_multiplier` = 成功率%（HP 非連動） |
| `restore_party` | HP/MP 回復 | `stat_multiplier` = 1〜99 で最大値の N% 回復。空なら全回復 |
| `apply_damage` | ランダム標的にダメージ | `fixed_damage`（`target_slot` 対象）。`stat_multiplier` = HP 下限（省略時 0） |
| `apply_damage_chosen` | 選択者にダメージ | `fixed_damage` |
| `apply_damage_party` | 全員ダメージ | `fixed_damage` |
| `grant_item` | アイテム付与 | `stat_attr` = item code, `stat_multiplier` = 個数 |
| `grant_gold` | ゴールド付与 | `stat_multiplier` = 付与量（例: 50, 200） |
| `stat_check_each_ally` | 生存者全員を順に判定 | `stat_attr` + `stat_multiplier` + `fixed_damage`（失敗時）。1 ノードで全員分の行を生成。**失敗行ごと**に `sync_party` + 行 `party`（累積 HP） |
| `assign_rescuer` | 助けた側を決定 | `target_slot` 以外から `chosen_slot` をランダム設定。以降 `{chosen_name}` = 助けた側 |
| `check_party_alive` | 全滅チェック | 生存→成功先 / 全滅→失敗先 |
| `start_battle` | 隠しボス等 | `next_default` = 敵 code（例: `inu_moe`） |
| `game_over` | 全滅処理 | 遷移先なし |
| `end` | イベント終了 | 必ず最後に1つ |

### 書き方のコツ

- ダメージ・回復・アイテム付与は **直前の narration/dialogue の表示後** に実行されます。  
  例: 「矢が刺さる！」→ `apply_damage` → 反応セリフ（[`trap_arrow`](../backend/database/csv/dungeon_event_nodes.csv) 参照）
- イベント末尾の **「一行は先に進むことにした」** は CSV 不要（エンジンが自動挿入）
- プレースホルダ: `{target_name}` `{chosen_name}` `{name}` `{success_rate}` `{stat_check_label}`
- 画面暗転: narration の `sfx=screen_fade`（背景画像のみ 1 秒暗転→自動次行。`ScenePanel` が暗転、`StorySequencePlayer` はテキスト表示を維持）
- HP 表示タイミング: [ダンジョン探索.md の HP/MP 表示タイミング](./ダンジョン探索.md#hpmp-表示タイミング必読実装規約) を必ず参照。DB コミットとフッター更新を混同しない

### speaker_role よく使う値

| 値 | 意味 |
|----|------|
| `target` | イベント開始時に選ばれたランダム味方 |
| `chosen` | プレイヤーが選んだ味方 |
| `random_ally` | 生存者からランダム（毎回変わる） |
| `random_ally_except_target` | target 以外からランダム |
| `random_ally_except_chosen` | chosen 以外からランダム |
| `random_ally_except_reactor` | reactor 以外からランダム |
| `random_ally_store` | 1人選んで以降固定（[`mysterious_presence`](../backend/database/csv/dungeon_event_nodes.csv) 参照） |
| `fixed:pc1` | 固定キャラ（pc1〜pc4） |

```mermaid

  intro --> react --> roll
```

## 5. 効果・アイテム・戦闘

### アイテム付与（宝箱型）

[`treasure_chest`](../backend/database/csv/dungeon_event_nodes.csv) と同じ3段構成:

1. `narration` … 「HP回復薬を手に入れた！」
2. `grant_item` … `stat_attr=potion_hp_s`, `stat_multiplier=1`
3. `end`

item code は [`item_masters.csv`](../backend/database/csv/item_masters.csv) 参照（例: `potion_hp_s`, `potion_mp_s`, `world_tree_leaf`）。

### ゴールド付与

[`gold_pickup`](../backend/database/csv/dungeon_event_nodes.csv) / [`trapped_chest`](../backend/database/csv/dungeon_event_nodes.csv):

1. `narration` … 「ゴールドを手に入れた！」など
2. `grant_gold` … `stat_multiplier=50`（付与量）
3. `end`

### 全員連続判定（鉄砲水型）

[`flash_flood`](../backend/database/csv/dungeon_event_nodes.csv): `stat_check_each_ally` … 生存メンバーのみ pc1→pc4 順。失敗時 `fixed_damage` でダメージ。**失敗行のみ** `sync_party` + 行 `party`（直前 narration には付けない）。暗転は別 narration + `sfx=screen_fade`。

### 助け役の割当（人喰い植物型）

[`man_eating_plant`](../backend/database/csv/dungeon_event_nodes.csv): 開始時 `target_slot` = 被害者 → `assign_rescuer` で `chosen_slot` = 助けた側 → `stat_check`（str ×4, `chosen_slot` 対象）。

### 隠しボス戦

[`mysterious_presence`](../backend/database/csv/dungeon_event_nodes.csv): `apply_damage_party` → `check_party_alive` → `start_battle` / `game_over`。

敵 code は [`enemy_masters.csv`](../backend/database/csv/enemy_masters.csv) を指定。

## 6. チェックリスト

- [ ] 全 node_key がイベント内でユニーク
- [ ] 分岐先 node_key が存在する（typo なし）
- [ ] 必ず `end` ノードで終わる
- [ ] `party_choice` の直後に `stat_check` がある場合、選択肢に成功率が出る（意図どおりか）
- [ ] dialogue の pc1〜4 は4人分すべて記載（空欄 OK だが意図的か確認）
- [ ] weight 合計・レア度の調整方針
- [ ] 新 node_type や特殊挙動が必要なら「エンジン拡張が必要」と明記

## 8. 実装側の作業（開発者向け）

企画データ受領後:

1. [`dungeon_events.csv`](../backend/database/csv/dungeon_events.csv) に1行追加
2. [`dungeon_event_nodes.csv`](../backend/database/csv/dungeon_event_nodes.csv) にノード行を追加
3. 新 `node_type` が必要なら [`DungeonExplorationEngine.php`](../backend/app/Services/Dungeon/Exploration/DungeonExplorationEngine.php) を拡張
4. `php artisan db:seed --class=MasterDataSeeder`
5. [`DungeonExplorationApiTest.php`](../backend/tests/Feature/DungeonExplorationApiTest.php) に完走テストを追加

テストでは `config('game.dungeon.test_force')` = `'exploration'` と `test_event_code` = 新 code で抽選を固定できます。判定固定は `test_stat_success` を使用。

```php
config([
    'game.dungeon.test_force' => 'exploration',
    'game.dungeon.test_event_code' => 'your_event_code',
    'game.dungeon.test_stat_success' => true, // 必要な場合
]);
```

新 node_type や新プレースホルダが必要な場合、CSV だけでは足りません。企画段階で「既存 type の組み合わせで表現できるか」を先に確認してください。
