# 戦闘の流れ

やみまほのターン制戦闘の仕様書です。プレイヤーが画面上で体験する流れと、戦闘中に起きることだけを記載しています。

キャラクターの能力値・ダメージ計算の詳細は [`キャラクターステータス.md`](キャラクターステータス.md) を参照してください。

---

## 概要

- **味方**: 4人パーティ（PC1・PC2・PC3・PC4）
- **敵**: 戦闘ごとに1〜3体（デモはコーモリ3体、ボスデモはイフリーヌ1体）
- **形式**: ターン制。順番が回ってきたキャラが行動する
- **勝利条件**: 敵をすべて倒す
- **敗北条件**: 味方がすべて倒れる

---

## ターン順

戦闘開始時に、**素早さが高いキャラから** 1ラウンドの順番が決まります（同じ素早さのときはスロット順）。

- 倒れたキャラは順番から外れます
- 味方の手番のときだけ、プレイヤーが操作できます
- 敵の手番は自動で進みます

---

## 1ラウンドの流れ（味方の手番）

### 1. 手番の確認

画面上部に「○○ のターン」と表示されます。光っている味方が、いま操作できるキャラです。

### 2. コマンドを選ぶ

手番の味方をタップすると、コマンド一覧が開きます。

| コマンド | 説明 |
|----------|------|
| **こぶし** | 物理攻撃。敵1体を選んでダメージを与える |
| **キック** | 物理攻撃。命中率50%だが威力は筋力×2（Lv10以降は×3） |
| **魔法** | キャラごとに、最初は 3 種類（覚えるにつれて増える）。MPを消費して効果を発動する。下の「コマンド画面の並び」 |

#### コマンド画面の並び（2026-11-14 から）

魔法や特技が増えてごちゃごちゃしないよう、**魔法・特技を「攻撃」「回復」「補助」の 3 つに大別**して、小さく薄いラベル（細い線つき）の下に並べます。

- **「こぶし」と「キック」は、どのラベルの下にも入れず、いつも一番上**に出ます（魔法の一覧が長くて、背の低い画面で収まらないときも、動きません。スクロールするのは魔法の一覧だけです）
- ラベルの順番は **攻撃 → 回復 → 補助**。ラベルの中の並びは、魔法ごとの `sort_order`（今までの並び順）のまま。魔法が 1 つもないラベルは出ません
- 分類（`spell_masters.csv` の **`category`** 列。`attack` / `heal` / `support`。空なら効果の種類から決まる。`SpellCategory`）:
  - **攻撃** … 敵にダメージを与える魔法（水の刃・水の凶刃・ツルの鞭・ツルの大槍・炎弾・爆破・大爆発・火炎波及・竜の息吹き・ブラックホール・石弾・岩落とし・流星群）
  - **回復** … HP を戻す・蘇生する・MP を戻す魔法（癒しの水・神聖の水・精霊の水・精霊の虹・**奇跡の虹・奇跡の雫**・宇宙樹の気配・宇宙樹の息吹・宇宙樹の雫・迅速調合・**応急手当**・**魔力集中**）
  - **補助** … バフ・デバフ・回避・障壁・加護（水の幻影・水の幻影群・ツルで縛る・爆樹・大爆樹・**闘志の旋律**・ラグオンビート・土の鎧・土の城壁・鋼の城壁・魔法障壁・命の加護）。敵の防御を下げる魔法（ツルで縛る・爆樹・大爆樹・ラグオンビート）は、ダメージがないので「補助」
  - 特技（迅速調合・応急手当・闘志の旋律）も、魔法と同じ分類に入ります
  - **魔力集中は「回復」**（MP を回復するため）にした。「補助」に動かしたいときは、`category` を `support` に書き換えるだけ
- サーバーは、各魔法に `category` を付けて返します（`commands.spells[].category`）。並べ替えとラベル付けは画面（`CommandModal.vue`）
- 魔法を足すときは、`spell_masters.csv` の `category` を書く（書き忘れても、効果の種類から決まる。新しい効果の種類を足したときは `SpellCategory` の表にも足す。`SpellCategoryTest` が見張る）

### 3. 対象を選ぶ

| 種類 | 操作 |
|------|------|
| こぶし・キック・単体攻撃魔法 | 攻撃する敵をタップ |
| 単体回復・単体バフ魔法 | 対象の味方をタップ |
| 全体攻撃魔法 | 対象を確認して **決定** ボタンを押す |

**魔法は、今は唱えられないときも、コマンド画面でいつでも選べます**（2026-11-14 から。以前は、MP が足りない・回復する相手がいない（全員満タン）・蘇生する相手がいない（誰も倒れていない）・魔力集中の条件を満たさない（HP が足りない／MP が満タン）魔法は押せなかった）。このゲームは、魔法を選ばないと「どんな魔法か」（説明・消費 MP）が分からないため。

- 唱えられない魔法も、コマンド画面では **ほかの魔法と同じ見た目**で出ます（グレーアウト・薄く表示もしない。2026-11-14 に、薄く出すのもやめた）
- 選ぶと、対象を選ぶ画面（`TargetOverlay.vue`。魔法の名前・説明・消費 MP が出る）に、赤い字で **「今は唱えられません：〜」**（理由）が出ます。理由は、「MPが足りません」「回復できる味方がいません」「戦闘不能の味方がいません」「HPが足りません」「MPが満タンです」「対象がいません」
- **そのあとの対象を選ぶ画面では、何も選べません**: どの味方・敵をタップしても選べず（立ち絵の選択状態が `locked`）、全体魔法の「唱える」ボタンは押せません。「やめる」か、画面のほかの場所のタップで、コマンド画面に戻れます。**自分に使う魔法（魔力集中）も、ほかの全体魔法と同じく、選ぶとすぐには唱えず、この画面（説明・消費 MP）が出て、「唱える」を押したら発動します**（2026-11-14 から。以前は選ぶと説明が出ないまま、すぐ発動していた）。唱えられないときは、「唱える」が押せず、理由が出ます
- サーバーは、各魔法に `usable`（唱えられるか）と **`unusable_reason`**（唱えられない理由。唱えられるなら null）を付けて返します（`BattleEngine::spellUnusableReason`）。唱えられない魔法の行動そのものは、今までどおりサーバーが受け付けません（`applyPlayerAction` が 422 になる。`BattleEngineUnusableSpellTest`）
- 探索中の「＋ 回復」画面（`DungeonHealModal.vue`）は、この変更の対象外で、使えないものは今までどおり灰色で押せません

### 4. 行動の解決

選び終えると演出が再生されます。

1. **行動メッセージ**（例: 「PC1のこぶし！」「PC1は癒しの水を詠唱した！」）
2. **ダメージ・回復エフェクト**（数値はフロート表示。HPバーはこのタイミングで減算）
3. 短い間隔のあと、次のイベントへ

ダメージ数値専用のバナーは表示しません。

### 5. 手番終了 → 敵フェーズ

味方1人の行動が終わると、続けて敵の手番が自動で進みます。

- 各敵はマスターに応じた行動を抽選します（通常攻撃・特技など）
- イフリーヌは「攻撃」「炎のキバ」「火炎放射」を確率で使用します
- **全員（味方と敵）の行動が一周したとき**（ラウンドの終わり）、まず全員のバフ・デバフの残りターンが 1 減り（[バフ・デバフ](#バフデバフ)）、そのあと、使い魔（Lv1 以上）がいれば支援の抽選が走ります（Lv1〜2 = 20%、Lv3〜6 = 30%、Lv7〜9 = 40%、Lv10 = 50%）。当たると「使い魔たちの支援行動！」のあと、敵への攻撃・味方の回復・攻撃バフ・蘇生のどれかが発動します。詳細は [使い魔.md](使い魔.md)

## 敵の手番

- 画面上部に「敵のターン」と表示されます
- プレイヤーは操作できません
- 行動前に「○○の攻撃！」「○○の炎のキバ！」などのメッセージが表示されます
- **敵画像の大きさ（フロント `EnemyRow.vue`）** … 画像は枠の幅いっぱいの正方形（縦横比は保つ）。幅の上限は敵の数と、ボス戦かどうかで変わる（`--enemy-slot-max`）。**通常戦は小さめ**（1 体 160px・2 体 125px・3 体以上 95px）、**ボス戦（階層ボス・中ボス＝`meta.boss` / `meta.mid_boss`）は迫力を出すため大きいまま**（1 体 260px・2 体 200px・3 体以上 140px）。数字は `EnemyRow.vue` の `SLOT_MAX_WIDTH`。高さの上限は敵エリア（`.field-top`、`container-type: size`）の高さから名前・HP バー分（56px）を引いた値（`100cqh`）で、画面が低い端末では自動で縮む。NPC（グース／カース）の画像は 600×1200 だが絵は上の約 40% だけ（下は透明）なので、`portrait` クラスで上 600×490 だけを切り出して表示する。ゼロ（`3_zero.png`、1280×600）は横長で、枠の幅に合わせると絵が小さくなるので、`wide` クラス（`WIDE_SPRITE_ASPECT`）で枠の 2.6 倍の幅（最大 420px）に広げ、枠の中央に合わせてはみ出して描く
- **ダメージの数字（フロント `EffectLayer.vue` の `.float-damage`）** … 出てから約 1.25 秒（`BattleView.vue` の `FLOATING_DAMAGE_MS`。以前は 0.9 秒）。出てすぐ薄くなり始めると見づらいので、約 7 割の間は濃いまま保ってから上へ流れて消える（`battle.css` の `floatDamageHold`）。**味方が受けたダメージ**（`.is-ally`）は、大きめ（2.1rem）・太字・赤い字に濃い縁取りで強調する（明るい立ち絵や暗い枠の上でも読めるように。端の味方でも画面からはみ出さないよう、左右 17%〜83% の間に寄せる）。敵が受けたダメージは従来の白い字
- **演出の順序（フロント `BattleView.vue` の `playEvents`）** … 敵は手番の開始で、どの敵の行動か分かるようにアイコンが前に出る（約0.28秒、`ENEMY_LUNGE_MS`）。物理攻撃は「動き終えてから告知」。**魔法の詠唱は動きを待たず**、PC の魔法と同じように手番の開始からすぐ（約0.17秒後）「○○は△△を唱えた！」を出す（動きと告知を同時に進める。動いてから遅れて出るとテンポが悪いため）。次のイベントが魔法の告知（魔法・特技。`spell_effect` / `spell_element` 付き）かどうかで判定する
- 敵の行動は [`enemy_skills.csv`](../backend/database/csv/enemy_skills.csv) の `weight`（比率）で抽選します。`action_type` は `punch`（攻撃）/ `physical_single` / `physical_all`（全体）/ `physical_double`（2 回行動する単体攻撃。下の「3 層の敵の技」）/ `spell` / `flee`（逃げる）
- `spell` の行は `skill_code` が `spell_masters.csv` の魔法コードです。対象・威力・「○○は△△を唱えた！」の魔法名は魔法側の定義で決まり、`target_type` と `coefficient` の列は使いません（空にしておく）。敵は MP を消費しません
- **即死魔法（刈り取る奴のソウルハント = `zaraki`）** … `effect=instant_death`、`power` が成功率（%、現在 10）。成功すると対象の残り HP 分のダメージとして扱い（「即死！」表示・闇属性のフラッシュ）、魔法障壁（次のダメージ無効）で防げます。外れると、その相手の位置に白い「miss」を出す（回避と同じ見せ方・同じ SE。`spell_failed` イベント。対象が複数のときは、1 人ずつ順番に約 0.4 秒おきに出る。2026-11-14 から。以前は「効果がなかった…」の文字だけが人数分続いて、何が起きたか分かりにくかった）。蘇生魔法（奇跡の雫など）が外れたときだけは、従来どおり「効果がなかった…」
- **敵の逃走（ミミック）** … ミミックは手番ごとに 50% で攻撃、50% で逃げます（`mimic,flee` 行）。逃げた敵は戦闘不能と同じ扱い（`alive=false`、`fled=true`）で、画面から消えます。**倒したわけではないので経験値・ゴールドは入りません**。敵が全員いなくなったら通常どおり勝利（結果画面は報酬なし）。逃げた敵は「倒した敵」に数えないため、イフリーヌの魔法習得などの条件にもなりません
- **2層ボスの技・魔法** … 強さの数値は [`enemy_masters.csv`](../backend/database/csv/enemy_masters.csv)、行動の比率は `enemy_skills.csv` の `weight` で決まります

- **行動ルール（`enemy_skill_rules.csv`）**: `enemy_code, rule, skill_code, value`。`rule` は `turns`（`1|5|10`）／ `every`（`5/3` = 5 ターン目から 3 ターンごと）／ `ally_fallen_once`（味方が倒れていたら、戦闘で 1 回だけ）／ `heal_below`（`70` = 回復は HP が 70% 未満の味方がいるときだけ）。ルールの無い敵は、今までどおり重みの抽選だけ。選択は `BattleEngine::chooseEnemySkill`（ユニットの `turns_taken`・`once_used`・`charge` を使う）

- テスト戦闘のボス戦プリセット `rift_boss`（「空間の裂け目」）で、いつでも戦える
- 一度でも裂け目のボス戦が始まったあとは、ダンジョンに潜る画面（層選択）の「時空の裂け目へ」ボタンからも、いつでも同じ戦闘を始められる（`POST /api/dungeon/rift`。勝てば毎回、報酬と全回復。詳細は [ダンジョン探索.md](ダンジョン探索.md)）

- **BGM**: 裂け目のボスに**勝ったときだけ**、戦闘が終わってもBGM（`last_boss`）を止めず（`battle_end` の `fadeOutBgm` を飛ばす）、エンドロールが終わるまで同じBGMが流れ続ける（BGM は `loop`）。エンドロールが終わって画面が切り替わると、そのルートのBGM（待機画面なら `home`）に変わる。負けたときは今までどおり戦闘終了で止まる。`leaveBattle` は、戦闘の state を**移動が終わってから**空にする（先に空にすると、ルートが切り替わる前に、BGM が一瞬だけ通常戦のものに変わってしまうため）

### HP 表示タイミング（実装規約）

- API の `state.units[].hp` は **その手の全イベント（味方＋敵フェーズ）適用後**の確定値
- フロントは `displayHp` で表示用 HP を管理し、イベント再生前にスナップショット／巻き戻ししてから `damage` イベントで減算する
- `displayHp` にキーがある間は `state.units[].hp` を HP バーに直接使わない（敵ターン開始時の一括減少を防ぐ）

### 命の加護

- 掛けた味方に「加護」状態（キャラ画像の左下に **加護** バッジ）がつきます。**ターンが経っても消えず**、発動するまで戦闘中ずっと続きます
- 戦闘不能になる攻撃（HP以上のダメージ。即死魔法ソウルハントも同じ扱い）を受けると、HP が 1 だけ残り、加護は消えます。受けたダメージは「残りHP − 1」に減ります
- 魔法障壁（次の被ダメージを無効化）が先に働きます。魔法障壁で防いだぶんは加護を消費しません
- 戦闘が終われば加護は残りません（戦闘ごとに掛け直し）

### 特技スタイル（魔法ではない特技）

`spell_masters.csv` の `cast_style` 列が `skill` の魔法は、魔法ではなく特技として扱います。発動時の告知が「〇〇は△△を唱えた！」ではなく「**〇〇の△△！**」になるだけで、**演出（フラッシュ・魔法の効果音・効果が出るまでの間・敵の手番のアイコンの動き）は魔法とまったく同じ**です（2026-11-14 から。以前は特技には出なかった）。裂け目のボス戦の敵の特技は、敵の魔法と同じ専用の音（`enemy_magic`）。画面は告知の文章の「唱え」ではなく、告知イベントに付く `spell_effect` / `spell_element`（魔法も特技も付く）で魔法の演出を出すかを決めています（`BattleView.vue` の `isSpellAnnounce`。`SkillCastAnnounceTest` で、特技の告知にも同じ項目が付くことを固定）。MPは通常どおり消費します。探索中の回復メニューでも、メッセージが「△△を唱えた。」ではなく「△△を使った。」になります（現在は迅速調合だけ）。

## バフ・デバフ

防御・攻撃のバフ／デバフは **「段階」**（2026-11-13 から）で管理します。最大で **3 段階上昇／3 段階低下**。キャラ画像の左下に、段階を **矢印の数** で表したバッジが出ます（例: 「防御↑↑」= 防御 2 段階上昇、「防御↓↓↓」= 防御 3 段階低下、「攻撃↑」= 攻撃 1 段階上昇。段階が 0 のときは出ません）。

| 段階 | 防御（上昇／低下） | 攻撃（上昇／低下） |
|------|------------------|------------------|
| 1 段階 | ×1.2 ／ ×0.8 | ×1.2 ／ ×0.8 |
| 2 段階 | ×1.4 ／ ×0.65 | ×1.4 ／ ×0.65 |
| 3 段階 | ×1.7 ／ ×0.5 | ×1.6 ／ ×0.5 |

- **防御** は防御・物理防御・魔法防御のすべてに、**攻撃** は筋力と魔力の両方に掛かります（回復量には乗りません）。倍率表は `config/battle.php` の `stage.multipliers`
- **重ねがけができ、段階は合算** … 鋼の城壁（防御+2）のあとに土の鎧（防御+1）を使うと、防御は 3 段階上昇
- **持続ターンは、かけた 1 回ごとに独立**（3 ターン）。**ラウンドの終わり（味方と敵の全員の行動が一周した直後）に、全員いっしょに 1 ずつ減ります**（2026-11-14 から。以前は「そのキャラ自身の行動のあとに 1 ずつ」減っていた）。「3 ターン」は **かけたラウンドを 1 ターン目と数える**（かけたラウンドの終わり・次のラウンドの終わり・その次のラウンドの終わりで切れる）。誰にかけても、**切れる時刻は同じ**で、かけた本人も他の味方と同じ長さ。例: 1 ラウンド目にサフィリアが鋼の城壁（全体）→ 4 人とも 3 ラウンド目の終わりに同時に切れる。残りターンは画面に出さず、内部（ユニットの `stages`。1 回の付与 = 1 要素）で数えています
  - **変更の理由**: 以前は、(1) 自分も対象に入る魔法は、かけた行動の終わりに自分だけ先に 1 減って実質 2 ターン、(2) 同じ魔法でも、かけた人より前に動く味方・後に動く味方で、切れる時刻（効く敵の行動の回数）が違う（例: 1 層のコーモリ戦でシエナが全体にかけると、他の 3 人は敵の行動 6 回ぶん・シエナ本人は 4 回ぶん）、(3) 味方が敵より先に動く並びでは、3 回目の自分の行動で切れるので、最後の 1 ターンは敵の攻撃を受ける前に切れていた、という不揃いがあった
  - **減らす順番**（`BattleEngine::afterAction`）: ラウンドが終わったら、①全員の持続を 1 減らす（`tickBuffsAtRoundEnd`。倒れているユニットは対象外）→ ②使い魔の支援の抽選（使い魔の攻撃バフは次のラウンドの頭の扱いなので、付けたばかりのものは減らされず、3 ラウンドぶん効く）。戦闘がそこで終わったときは減らさない
  - **敵のバフ・デバフも同じ**（敵が自分たちにかけた防御アップも、プレイヤーが敵にかけたデバフも、ラウンドの終わりに減る）。回避の固定（`buffs`）も同じ。命の加護・魔法障壁は、ターンが経っても消えない（従来どおり）
- **バフとデバフは合算** … 防御+2 のところにジャミング（-1）を受けると +1、そこに大爆樹（-2）を受けると -1（防御 1 段階低下）。デバフが先に切れれば、バフが戻ってきます
- **上限（+3／-3）を超えてかけたときは、上限いっぱいまでかかった状態になります**（2026-11-14 に仕様を変更。以前は「超えた分は無駄」で、上限に収まる差分だけを記録していた）。かけた量はそのまま（ラグオンビートなら -3）記録し、**段階は、付いている効果の合計を +3／-3 に丸めて読む**（`BattleEngine::currentStage`）。例: 防御-1 のキャラがラグオンビートを使うと、防御は -3 段階になる（-4 とはならない）。先にかかっていた -1 が切れても、新しくかけた -3 の持続（3 ターン）のあいだは -3 のまま。以前は、差分の -2 だけを記録していたので、先の効果の最後の 1 ターンが同じ行動の終わりに切れると、新しい効果が薄まって、自分の防御が変わらない（さらには上がる）ことがあった（防御-1〜-2 の状態から使った約 4,400 通りのうち約 25%）。すでに上限のところに同じ向きの効果をかけても、効果は足されて、先の効果が切れたあとも上限が続く。画面のバッジに出る段階と、イベントの `applied` は、かけた瞬間に見た目の段階が変わった量（上限で頭打ちの分は含まない）。バフとデバフの合算は変わらず、足した合計を丸める（防御+3 のところに -3 をかければ 0。ただし、バフを何度も重ねがけして合計が +6 になっていると、-3 をかけても +3 のまま、というように、重ねた分だけ打ち消されにくくなる）
- クリティカルは、防御側のバフ／デバフ（防御の段階）を無視します（従来どおり）
- **戦闘不能になったキャラ（敵味方どちらも）からは、バフとデバフがすべて消えます**（2026-11-14 から）。防御・攻撃の段階（バフもデバフも、使い魔の攻撃バフも）、回避の固定、命の加護・魔法障壁（`stages` / `buffs` / `life_ward` / `damage_shield`）、敵の詠唱の途中経過（`charge`）が対象です。**蘇生しても戻りません**（蘇生後は何も付いていない状態から始まり、新しくバフ・デバフを受けられます）。実装は `BattleEngine::applyDamage` の戦闘不能の分岐から呼ぶ `clearEffectsOnDown`（HP が 0 になる経路はここだけ。命の加護で踏みとどまったときは倒れていないので、効果は残ります）。逃げた敵は倒れたわけではないので対象外です
- **画面のバッジは、サーバーが送る「その時点の状態」をそのまま表示します**（2026-11-14 から）。バフ・デバフが付いたときの `buff_applied` と、ラウンドの終わりに持続が切れたときの `buff_expired`（切れたものがあったユニットごとに 1 つ。`target`）が、どちらも **`stages`（防御・攻撃の現在の段階 `{def, atk}`。-3〜+3）と `buffs`（回避などの残りターンつき効果）** を持っていて、画面（`BattleView.vue` の `applyBadgeForBuff`）はそのユニットのバッジをこの値に置き換えるだけです。以前は、`buff_applied` の `applied`（かけた瞬間に見た目が変わった量）を画面側で足していて、切れたことを知らせるイベントも無く、バッジはやり取りの最後（次の入力待ち）にまとめて state に合わせていた。そのため、サーバーでは切れているのに、敵のターン中ずっと「防御↑↑」が出たままになったり、画面の段階の数字が本当とずれたり（防御+2 が切れた後に -3 を受けて、画面は -1・実際は -3、など）した。`applied` はイベントに残してある（古い形式のイベントのときだけ画面が足す）。`buff_expired` に演出（効果音・文字）はなく、バッジが消えるだけ

## 回避・クリティカル

- **味方の回避率** … デフォルト5%
- **敵の回避率** … マスター値（デフォルト1%）
- **敵が味方を攻撃するとき** … 物理攻撃にもダメージ魔法（即死魔法を含む）にも、味方の回避率（素の5%）で回避判定が入ります。成功すると、ダメージの数字と同じ位置（狙われた味方）に白い「miss」が出ます。全体技・全体魔法は対象ごとに判定します。デバフ・回復・バフは回避できません
- **味方が敵を攻撃するとき** … 素の回避率で判定するのは通常の「こぶし」だけです（キック・魔法には効きません）
- **回避バフ（水の幻影など）がかかっている間は**、回避率がバフの値（60%／30%）に固定されます。バフがかかっている相手には、キックやダメージ魔法にも回避判定が入ります
- **外れたときの表示** … 味方の攻撃が敵に外れたときも、敵の攻撃が味方に外れたときも、狙われたユニットの位置に、ダメージの数字と同じ動きで白い「miss」が出ます（外れの SE も鳴ります。画面中央の「攻撃は外れた」のバナーは廃止）。表示は `BattleView.vue` の `showFloatingDamage(…, miss = true)` と `EffectLayer.vue` の `.is-miss`
- **味方のクリティカル率** … デフォルト5%
- **敵のクリティカル率** … マスター値（デフォルト1%）
- クリティカル時は相手の防御力を0としてダメージを算出します

## ダメージの考え方

- **こぶし** … 筋力ベース。回避判定あり。Lv10以降は係数 1.5
- **キック** … 命中率50%固定。命中時は筋力×2（Lv10以降は×3）
- **魔法** … 魔力ベース（回復・バフは別処理）
- HPが0になると、そのキャラは戦闘不能になります

## 勝敗

### 勝利

敵すべてのHPが0になったとき、**勝利！** と表示されます。

- **戦闘中に倒れた味方は、戦闘が終わっても倒れたまま**（HP 0）です。即死魔法で倒れた場合も同じです。探索画面の「＋ 回復」で、蘇生の魔法か宇宙樹の葉を使うと戻ります
- **経験値は、戦闘不能のまま戦闘を終えた味方にも入ります**（2026-11-14 から。以前は生きている味方だけで、倒れた味方には入らなかった）。生きている味方と同じ量で、結果画面にも「〇〇は△△の経験値を得た」が出ます。敗北・逃走では入りません（勝利したときだけ）
- **戦闘不能のまま経験値でレベルアップしても、復活しません**（HP は 0 のまま）。レベルアップは最大HP・最大MPが増え、現在の HP・MP も増加分だけ増える（実質的な回復）仕様ですが、戦闘不能のキャラは HP の増加分を足しません（`LevelGrowthService::grantExp`。経験値を足す前に HP 0 かを見て、HP を 0 に保つ）。最大HPは増えているので、蘇生したときにその分が反映されます。MP は生きているキャラと同じく、増加分が足されます。筋力・魔力・防御などの上昇は、生きているキャラと同じように反映されます。管理画面の「経験値配布」（`AdminPartyService::grantExpToParty`）も同じ `grantExp` を通るので、戦闘不能のキャラは HP 0 のままです
- 倒れるまでに使った MP も、戦闘後のステータスに反映されます（`BattleRewardService::applyVictoryRewards`）。以前は倒れた味方の HP・MP を保存しておらず、戦闘前の HP に戻って「復活」して見えるバグがあった（2026-11-12 修正）

戦闘の途中でブラウザを再読み込みしても、HP・手番・MPなどの状態は続きから再開できます。ただし、再読み込み直前の演出は再生されません。
