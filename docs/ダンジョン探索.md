# ダンジョン探索

やみまほのダンジョン画面（`/dungeon`）の仕様です。待機画面からダンジョンに入り、「進む」で深さを進めながら戦闘または探索イベントが発生します。

---

## 1. 概要

1. 待機画面で「ダンジョンへ」→ `POST /api/dungeon/enter`
2. ダンジョン画面で「進む」→ `POST /api/dungeon/advance`
3. 応答に応じて戦闘画面へ遷移するか、探索イベント（セリフ・選択）を再生する
4. 探索イベント完了後、再び「進む」可能

---

## 2. 層（floor）と深さ（step）

### 層

- ダンジョンは **1〜3 層**（`game.dungeon.max_floor`）
- 現状プレイ可能なのは **1 層のみ**（`game.dungeon.playable_floor`）
- `user_dungeon_progress.floor` … 現在挑戦中の層
- `user_dungeon_progress.unlocked_floor` … 解放済みの最深層（ボス撃破で +1）
- 入場: `POST /api/dungeon/enter` に `{ "floor": 1 }` を指定
- 2 層目以降の敵・イベントは未実装のため、1 層ボス撃破で `unlocked_floor` が 2 になっても **2 層には入れない**（403）

### 深さ

- `user_dungeon_progress.step` が深さ（0 から開始、進むたびに +1）
- 各層の最深部（ボス）の深さは `game.dungeon.floors.{N}.boss_step`（1 層は **31**）
- 1 層の通常戦闘は深さ帯で出現敵が変わる（`encounter_bands`）。敵マスタは `enemy_masters.csv` の `floor` 列で層別
  - 深さ 1〜10: コーモリ（`bat`）2〜3 匹
  - 深さ 11〜20: コーモリとヘビビ（`bat` / `snake`）合計 2〜3 匹
  - 深さ 21〜30: ヘビビとムシプリンス（`snake` / `beetle`）合計 2〜3 匹
  - 深さ 31: ボス イフリーヌ（`inu_moe`）1 匹
- ボス深度に到達した「進む」は **必ずボス戦**（通常抽選なし）
- **リセット条件**
  - ダンジョン由来の戦闘で **敗北** したとき（`BattleOrchestrator`）
  - 管理画面で「ダンジョン探索リセット」をオンにして適用したとき
- 通常戦闘 **勝利** では深さは維持
- **ボス撃破** では深さを 0 にリセットし、次の層が解放される（`dungeon_floor_cleared` イベント）

## 3. 1 回の「進む」での抽選

定数は [`backend/config/game.php`](../backend/config/game.php) の `dungeon` 配列（CSV にはしない）。

| 定数 | 既定値 | 意味 |
|------|--------|------|
| `battle_encounter_rate` | 30 | 戦闘（敵出現）になる確率（%） |
| `exploration_event_rate` | 70 | 探索イベント（参考値、戦闘と合計 100 想定） |

- `skip_battle_encounters` が ON のユーザーは **常に探索イベント**
- それ以外は `random_int(1, 100)` で戦闘か探索かを決定
- 探索イベントの種類は `dungeon_event_masters` の weight で抽選（1 層の weight 合計は **100**）

#### 1 層イベント weight（参考）

| code | name | weight |
|------|------|--------|
| trap_arrow | 矢のトラップ | 24 |
| treasure_chest | 宝箱 | 24 |
| healing_spring | 回復の泉 | 19 |
| suspicious_spring | あやしい回復の泉 | 19 |
| mysterious_presence | 謎の気配 | 9 |
| rainbow_spring | 虹色の回復の泉（レア） | 5 |

## 4. 戦闘エンカウント

- 敵マスタ: [`enemy_masters.csv`](../backend/database/csv/enemy_masters.csv)（`floor` 列で層別）
- 出現組み合わせ: `config/game.php` の `dungeon.floors.{N}.encounter_bands` と `boss_enemy_code`（`DungeonStepEncounterBuilder`）
- ボス深度では `boss_step` の「進む」で必ずボス戦（通常の 30% 抽選は行わない）
- 戦闘メタ: `source=dungeon`, `floor`, `step`, `boss`, `can_flee`
- **逃げる**（ダンジョン戦闘・ボス以外）: `POST /battles/{id}/actions` に `action=flee`。100% 成功し深さを 3 減らす（最低 1）。戦闘状態は `fled`
- **撤退する**（ダンジョン画面）: `POST /dungeon/retreat`。所持金を `ceil(所持金 × 0.8)` にし、探索セッションを破棄して待機画面へ。層・深さは維持

### 所持金

- `users.gold`（パーティ共有）。初期値 0
- hub / dungeon の HUD（左上 DAY・右上 所持金）で表示
- API: `GET /player/party` および `GET /dungeon` の `gold` フィールド

## 5. 探索イベント

### セッション

- テーブル: `dungeon_exploration_sessions`
- 進行中は `advance` を **409** で拒否
- 完了時にセッション削除・パーティ HP を API で返却

### segment の種類

| kind | クライアント動作 |
|------|------------------|
| `story` | `StorySequencePlayer` で `lines` をタップ送り（`sync_party` 行でゲージ更新）→ `POST /dungeon/exploration/continue` |
| `choice` | 生存メンバー選択（`lines` があれば先にストーリー再生）→ `POST /dungeon/exploration/choose` |
| `complete` | 終了。パーティ再表示、「進む」復帰 |

イベント終了直前に、エンジンが固定の締め描写 **「一行は先に進むことにした」**（地の文）を必ず 1 行挿入します（CSV 不要）。

### API

| メソッド | パス | ボディ |
|----------|------|--------|
| GET | `/api/dungeon` | —（`step` のみ） |
| POST | `/api/dungeon/enter` | — |
| POST | `/api/dungeon/advance` | — |
| POST | `/api/dungeon/exploration/continue` | `{ "session_id": "uuid" }` |
| POST | `/api/dungeon/exploration/choose` | `{ "session_id", "slot_id" }` |

### 実装クラス（バックエンド）

- `DungeonEventCatalog` … イベント・ノード取得
- `DungeonExplorationEngine` … ノード実行・判定・ダメージ
- `DungeonExplorationService` … start / continue / choose
- `PartyExplorationDamageService` … スロット指定ダメージ

## 6. CSV リファレンス

### dungeon_events.csv

| 列 | 説明 |
|----|------|
| code | イベント ID |
| floor | 出現層（1〜3） |
| name | 表示名 |
| weight | 抽選 weight |
| event_type | 拡張用タイプ名 |
| start_node_key | 開始ノード |

### dungeon_event_nodes.csv

| 列 | 説明 |
|----|------|
| event_code / node_key | 複合キー |
| node_type | 下表 |
| text | テンプレート（`{target_name}` `{chosen_name}` `{success_rate}` `{stat_check_label}`、改行は `\n`） |
| speaker_role | `target` / `chosen` / `random_ally` / `random_ally_except_target` / `fixed:pc1` など |
| dialogue_pc1〜pc4 | スロット別セリフ |
| stat_attr / stat_multiplier | `stat_check` 用（成功率 = min(100, ceil(能力値 × 倍率 × 現在HP/最大HP))） |
| fixed_damage | `apply_damage` 用 |
| sfx | `attack` など（フロントで SE 再生） |
| next_on_success / next_on_fail / next_default | 遷移先ノード key |

#### node_type 一覧

| type | 動作 |
|------|------|
| narration | 地の文 1 行 |
| dialogue | セリフ 1 行（話者は speaker_role + dialogue_pc*） |
| stat_check | 判定（表示後、continue でロール） |
| party_choice | 生存者選択 UI（`next_on_success` で次ノード） |
| party_choice_skip | 生存者選択 + `dialogue_pc4` のスキップ肢（`next_on_fail`） |
| binary_choice | はい / いいえ（`dialogue_pc1` / `dialogue_pc2` がラベル） |
| restore_party | HP/MP 回復（**直前の表示行のあと**に実行）。`stat_multiplier` に 1〜99 で最大 HP/MP の N% を加算、未設定時は全回復 |
| apply_damage_chosen | `chosen_slot` に固定ダメージ（**直前の表示行のあと**に実行） |
| apply_damage_party | パーティー全員に固定ダメージ（同上） |
| chance_branch | `stat_multiplier` を成功率（%）として分岐 |
| check_party_alive | 全滅なら `next_on_fail`、生存なら `next_on_success` |
| start_battle | 探索終了後にボス戦開始（`next_default` = 敵 code） |
| game_over | 全滅処理（深さリセット） |
| apply_damage | 固定ダメージ（`target_slot`、**直前の表示行のあと**に実行） |
| end | セッション終了 |

`apply_damage` / `apply_damage_chosen` / `apply_damage_party` / `restore_party` / `check_party_alive` は、**直前の narration / dialogue を返すセグメントを組み立てる時点で DB にコミット**します（ブラウザバック等で未処理のまま残らない）。フロントは API の `party_snapshot`（コミット前）と `party`（コミット後）を受け取り、直前の行に `sync_party: true` が付いているタイミングでフッターの HP/MP を更新します。グラフ上は「セリフ → 効果ノード → 結果の地の文」の順に並べてください。

### dungeon_encounters.csv

`enemies_json` に `[{"slot","master_code","name"}, ...]` を JSON で記載。

## 7. イベントグラフ

### 矢のトラップ（trap_arrow）

```mermaid
flowchart TD
  intro --> intro_react --> dodge_preview --> roll
  roll -->|成功| success_narr --> success_dialogue --> end
  roll -->|失敗| fail_narr --> fail_damage --> fail_ally --> fail_target --> end
```

### 回復の泉（healing_spring）・あやしい回復の泉（当たり）

```mermaid
flowchart TD
  intro --> react --> heal["restore_party（20%）"] --> after --> end
```

`healing_spring` の `heal` と `suspicious_spring` の `taste_ok_heal` は `stat_multiplier=20`。

### 虹色の回復の泉（rainbow_spring・レア）

```mermaid
flowchart TD
  intro --> react --> heal["restore_party（全回復）"] --> after --> end
```

weight **5**（探索イベント抽選内）。`stat_multiplier` 未設定で全回復。

### 宝箱（treasure_chest）

```mermaid
flowchart TD
  found --> found_rust --> ally_comment --> choose
  choose --> force_open --> str_roll
  str_roll -->|成功| open_success --> herb --> end
  str_roll -->|失敗| open_fail --> fail_dialogue --> end
```

## 8. テキスト・判定・SE

- 置換: `{target_name}`, `{chosen_name}`, `{name}`, `{success_rate}`, `{stat_check_label}`（例: 素早さ判定 / 筋力判定）
- ステータス判定の成功率: `min(100, ceil(能力値 × stat_multiplier × (現在HP / 最大HP)))`（端数切り上げ）
- `party_choice` で直後に `stat_check` がある場合: プロンプト先頭に判定名、各選択肢は `名前（成功率N%）`
- 地の文プレビュー（`dodge_preview` / `force_open` など）: `{stat_check_label}` と `{success_rate}` を併記
- `chance_branch` は CSV の `stat_multiplier` をそのまま成功率（%）として使用（HP 乗算なし）
- 判定ロール: `random_int(1, 100) <= 成功率`
- 判定直後の API: `segment.stat_check_result` が `"success"` または `"fail"`（フロントで `success` / `miss` SE）
- ストーリー送りタップ: `se/cursor.mp3`（行 `sfx` による攻撃 SE は廃止）
- ダンジョン「進む」: `se/cursor.mp3`（ストーリー送りと同じクリック音）
- BGM（BGM ON 時）: ホーム `bgm/home.mp3`、ダンジョン `bgm/dungeon.mp3`、通常戦闘 `bgm/battle.mp3`、ボス `bgm/boss_battle_2.mp3`

## 9. 管理画面（/admin）

`POST /api/admins/dungeon-settings`

```json
{
  "skip_battles": true,
  "reset_progress": false
}
```

| フラグ | 動作 |
|--------|------|
| skip_battles | デモユーザーの `skip_battle_encounters` を永続更新 |
| reset_progress | **このリクエスト時のみ** `step = 0` にリセット |

## 10. 拡張手順

1. `dungeon_events.csv` に行追加、`dungeon_event_nodes.csv` にノード列を追加
2. `php artisan db:seed --class=MasterDataSeeder`（またはデプロイ時 seed）
3. 新 `event_type` が必要なら `DungeonExplorationEngine` に分岐を追加
4. 固定深度トリガー（旧 step3 匂いストーリー等）は将来 `dungeon_depth_triggers` などで対応可能
