# ダンジョン探索

やみまほのダンジョン画面（`/dungeon`）の仕様です。待機画面からダンジョンに入り、「進む」で深さを進めながら戦闘または探索イベントが発生します。

**新規イベント追加:** 企画データの渡し方は [ダンジョンイベント企画テンプレ.md](./ダンジョンイベント企画テンプレ.md) を参照。

---

## 1. 概要

1. 待機画面で「ダンジョンへ」→ `POST /api/dungeon/enter`
2. ダンジョン画面で「進む」→ `POST /api/dungeon/advance`
3. 応答に応じて戦闘画面へ遷移するか、探索イベント（セリフ・選択）を再生する
4. 探索イベント完了後、再び「進む」可能

---

## 2. 層（floor）と深さ（step）

### 層

- ダンジョンは **1〜3 層**（`game.dungeon.max_floor`）
- 現状プレイ可能なのは **1〜2 層**（`game.dungeon.playable_floor` = 2）
- `user_dungeon_progress.floor` … 現在挑戦中の層
- `user_dungeon_progress.unlocked_floor` … 解放済みの最深層（ボス撃破で +1）
- 入場: `POST /api/dungeon/enter` に `{ "floor": N }` を指定（Hub では解放済み層ごとにボタン表示）
- 未解放の層・未実装の層へは **403**

### 2 層（仮実装）

- ボス深度 **41**（`game.dungeon.floors.2.boss_step`）
- 通常戦闘の敵構成は 1 層と同じ（`enemy_masters.csv` に floor=2 行）
- 探索イベントは 1 層と同じ code を `dungeon_events.csv` の floor=2 行で抽選（**ノード CSV は共有**）
- 能力値判定の倍率は [`dungeon_floor_masters`](../backend/database/csv/dungeon_floors.csv) の `stat_multiplier_scale` で層差分（2 層 = 50 → 1 層の半分、切り上げ）

### 深さ

- `user_dungeon_progress.step` が深さ（0 から開始、進むたびに +1）
- 各層の最深部（ボス）の深さは `game.dungeon.floors.{N}.boss_step`（1 層 **31**、2 層 **41**）
- 1 層の通常戦闘は深さ帯で出現敵が変わる（`encounter_bands`）。敵マスタは `enemy_masters.csv` の `floor` 列で層別
  - 深さ 1〜10: コーモリ（`bat`）2〜3 匹
  - 深さ 11〜20: コーモリとヘビビ（`bat` / `snake`）合計 2〜3 匹
  - 深さ 21〜30: ヘビビとムシプリンス（`snake` / `beetle`）合計 2〜3 匹
  - 深さ 31: ボス イフリーヌ（`inu_moe`）1 匹
- 2 層も上記と同じ敵帯（深さ 31〜40 も snake/beetle）。深さ **41** でボス
- ボス深度に到達した「進む」は **必ずボス戦**（通常抽選なし）
- **リセット条件**
  - ダンジョン由来の戦闘で **敗北** したとき（`BattleOrchestrator`）
  - 管理画面で「ダンジョン探索リセット」をオンにして適用したとき
- 通常戦闘 **勝利** では深さは維持
- **ボス撃破** では深さを 0 にリセットし、次の層が解放される（`dungeon_floor_cleared` イベント）

## 3. 1 回の「進む」での抽選

定数は [`backend/config/game.php`](../backend/config/game.php) の `dungeon` 配列（CSV にはしない）。

| 定数 | 既定値 | 意味 |
|------|--------|------|
| `battle_encounter_rate` | 30 | 戦闘（敵出現）になる確率（%） |
| `exploration_event_rate` | 60 | 探索イベントになる確率（%） |
| `flavor_narrative_rate` | 10 | ただの描写（フレーバーテキスト）になる確率（%） |

- `skip_battle_encounters` が ON のユーザーは **戦闘なし**（ボス深度を除く）。その場合、戦闘分 30% は探索イベントに振り替え、**イベント 90% / 描写 10%**
- それ以外は `random_int(1, 100)` で戦闘・イベント・描写のいずれかを決定
- 探索イベントの種類は `dungeon_event_masters` の weight で抽選（1 層の weight 合計は **100** が目安）

> **要調整:** 2026-06 時点で 1 層イベント weight 合計は **132**（新規 4 件は仮値 `8` ずつ）。`dungeon_events.csv` の weight のみ変更すれば抽選比率を調整できます。

#### 1 層イベント weight（参考）

| code | name | weight |
|------|------|--------|
| trap_arrow | 矢のトラップ | 25 |
| treasure_chest | 宝箱 | 30 |
| healing_spring | 回復の泉 | 7 |
| suspicious_spring | あやしい回復の泉 | 25 |
| mysterious_presence | 謎の気配 | 10 |
| rainbow_spring | 虹色の回復の泉（レア） | 3 |
| gold_pickup | お金取得 | 8（仮） |
| flash_flood | 鉄砲水 | 8（仮） |
| man_eating_plant | 人喰い植物 | 8（仮） |
| trapped_chest | 宝箱（トラップあり） | 8（仮） |

## 4. 戦闘エンカウント

- 敵マスタ: [`enemy_masters.csv`](../backend/database/csv/enemy_masters.csv)（`floor` 列で層別）
- 出現組み合わせ: `config/game.php` の `dungeon.floors.{N}.encounter_bands` と `boss_enemy_code`（`DungeonStepEncounterBuilder`）
- ボス深度では `boss_step` の「進む」で必ずボス戦（通常の 30% 抽選は行わない）
- 戦闘メタ: `source=dungeon`, `floor`, `step`, `boss`, `can_flee`
- **逃げる**（ダンジョン戦闘・ボス以外）: `POST /battles/{id}/actions` に `action=flee`。100% 成功し深さを 1 減らす（最低 1）。戦闘状態は `fled`
- **撤退する**（ダンジョン画面）: `POST /dungeon/retreat`。所持金を `ceil(所持金 × 0.9)` にし、探索セッションを破棄して待機画面へ。層・深さは維持。**パーティ全員の HP/MP を最大まで回復**

### 所持金

- `users.gold`（パーティ共有）。初期値 0
- hub / dungeon の HUD（左上 DAY・右上 所持金）で表示
- API: `GET /player/party` および `GET /dungeon` の `gold` フィールド

## 4.5 ただの描写（flavor）

「進む」で **10%** の確率で発生。探索セッションは作らず、`POST /api/dungeon/advance` の応答で `event: "flavor"` と `segment.kind: "story"` を返します。

- フロントは `StorySequencePlayer` で表示し、終了後そのまま「進む」可能
- パーティ状態・所持品・ゴールドへの影響なし
- 文言は [`DungeonFlavorNarrativeService.php`](../backend/app/Services/Dungeon/DungeonFlavorNarrativeService.php) の3パターンからランダム

---

### セッション

- テーブル: `dungeon_exploration_sessions`
- 進行中は `advance` を **409** で拒否
- 完了時にセッション削除・パーティ HP を API で返却

### segment の種類

| kind | クライアント動作 |
|------|------------------|
| `story` | `StorySequencePlayer` で `lines` をタップ送り（`sync_party` 行でゲージ更新）→ `POST /dungeon/exploration/continue` |
| `choice` | 生存メンバー選択（`lines` があれば先にストーリー再生）→ `POST /dungeon/exploration/choose` |
| `complete` | 終了。パーティ再表示、「進む」復帰 |

イベント終了直前に、エンジンが固定の締め描写 **「一行は先に進むことにした」**（地の文）を必ず 1 行挿入します（CSV 不要）。

### API

| メソッド | パス | ボディ |
|----------|------|--------|
| GET | `/api/dungeon` | —（`step` のみ） |
| POST | `/api/dungeon/enter` | — |
| POST | `/api/dungeon/advance` | — |
| POST | `/api/dungeon/exploration/continue` | `{ "session_id": "uuid" }` |
| POST | `/api/dungeon/exploration/choose` | `{ "session_id", "slot_id" }` |

### 実装クラス（バックエンド）

- `DungeonEventCatalog` … イベント・ノード取得
- `DungeonExplorationEngine` … ノード実行・判定・ダメージ
- `DungeonExplorationService` … start / continue / choose
- `PartyExplorationDamageService` … スロット指定ダメージ

## 6. CSV リファレンス

### dungeon_events.csv

| 列 | 説明 |
|----|------|
| code | イベント ID |
| floor | 出現層（1〜3） |
| name | 表示名 |
| weight | 抽選 weight |
| event_type | 拡張用タイプ名 |
| start_node_key | 開始ノード |

### dungeon_event_nodes.csv

| 列 | 説明 |
|----|------|
| event_code / node_key | 複合キー |
| node_type | 下表 |
| text | テンプレート（`{target_name}` `{chosen_name}` `{success_rate}` `{stat_check_label}`、改行は `\n`） |
| speaker_role | `target` / `chosen` / `random_ally` / `random_ally_except_target` / `fixed:pc1` など |
| dialogue_pc1〜pc4 | スロット別セリフ |
| stat_attr / stat_multiplier | `stat_check` 用（ノードの `stat_multiplier` × 層の `stat_multiplier_scale` を判定倍率に使用。成功率 = min(95, ceil(能力値 × scaledMultiplier × 現在HP/最大HP))）。`grant_item` では item code / 個数。`grant_gold` では付与量。`apply_damage` / `apply_damage_chosen` では `stat_multiplier` = HP 下限（例: `1` で最低 1 HP） |
| fixed_damage | `apply_damage` / `apply_damage_party` / `stat_check_each_ally` 用 |
| sfx | `attack` など（フロントで SE 再生）。`screen_fade` は**背景画像のみ** 1 秒暗転（テキスト窓・パーティ欄はそのまま。`ScenePanel` 側でオーバーレイ） |
| next_on_success / next_on_fail / next_default | 遷移先ノード key |

#### node_type 一覧

| type | 動作 |
|------|------|
| narration | 地の文 1 行 |
| dialogue | セリフ 1 行（話者は speaker_role + dialogue_pc*） |
| stat_check | 判定（表示後、continue でロール） |
| stat_check_each_ally | 生存メンバー全員を pc1→pc4 順に判定（1 ノードで一括ロール・行生成）。`fixed_damage` = 失敗時ダメージ |
| assign_rescuer | `target_slot` 以外の生存者から `chosen_slot`（助けた側）をランダム設定 |
| party_choice | 生存者選択 UI（`next_on_success` で次ノード） |
| party_choice_skip | 生存者選択 + `dialogue_pc4` のスキップ肢（`next_on_fail`） |
| binary_choice | はい / いいえ（`dialogue_pc1` / `dialogue_pc2` がラベル） |
| restore_party | HP/MP 回復（**直前の表示行のあと**に実行）。`stat_multiplier` に 1〜99 で最大 HP/MP の N% を加算、未設定時は全回復 |
| apply_damage_chosen | `chosen_slot` に固定ダメージ（**直前の表示行のあと**に実行） |
| apply_damage_party | パーティー全員に固定ダメージ（同上） |
| chance_branch | `stat_multiplier` を成功率（%）として分岐 |
| check_party_alive | 全滅なら `next_on_fail`、生存なら `next_on_success` |
| start_battle | 探索終了後にボス戦開始（`next_default` = 敵 code） |
| game_over | 全滅処理（深さリセット） |
| apply_damage | 固定ダメージ（`target_slot`、**直前の表示行のあと**に実行）。`stat_multiplier` = HP 下限 |
| grant_item | アイテム付与（**直前の表示行のあと**に実行）。`stat_attr` = item code、`stat_multiplier` = 個数 |
| grant_gold | ゴールド付与（同上）。`stat_multiplier` = 付与量 |
| end | セッション終了 |

`apply_damage` / `apply_damage_chosen` / `apply_damage_party` / `restore_party` / `check_party_alive` / `grant_item` / `grant_gold` / `stat_check_each_ally` は、**直前の narration / dialogue を返すセグメントを組み立てる時点で DB にコミット**します（ブラウザバック等で未処理のまま残らない）。フロントは API の `party_snapshot`（コミット前）と `party`（コミット後）を受け取り、**結果を描写している行**に `sync_party: true` が付いているタイミングでフッターの HP/MP を更新します。

#### HP/MP 表示タイミング（必読・実装規約）

| 原則 | 内容 |
|------|------|
| DB と UI の分離 | **DB への反映は早くてよい**（セグメント生成時にコミット）。**フッター HP の更新は描写と同時** |
| `sync_party` | プレイヤーに「効果が起きた」と見せる行に付ける。`StorySequencePlayer` がその行表示時に `sync-party` を emit |
| `party_snapshot` | 効果適用前のパーティ。初回表示用 |
| `party`（API ルート） | セグメント内の全効果適用後の最終パーティ |
| `party`（行メタ） | **複数人へ順次ダメージ/回復**（`stat_check_each_ally` 等）では、各行の `party` に**その時点までの累積結果**を載せ、`sync_party` とセットで送る |

**グラフ設計:** 「結果の地の文／セリフ → 効果ノード → 次の描写」の順。効果ノード直前の表示行に `sync_party`（deferred 系はエンジンが自動付与）。

**既存イベント監査（2026-06）:**

| イベント | 判定 |
|----------|------|
| trap_arrow 失敗 | OK（`fail_narr` 表示時に sync） |
| suspicious_spring ハズレ | OK（「マズイ」セリフ表示時に sync） |
| treasure_chest / trapped_chest 報酬 | OK（報酬地の文の直前で sync） |
| man_eating_plant 失敗ダメージ | OK（deferred `apply_damage`） |
| trapped_chest 爆発 | OK（全員同時ダメージ → `boom` 1 回 sync で正しい） |
| flash_flood 精神判定 | **修正済** — 失敗行ごとに sync + `party`。直前の「水に飲まれた」行に `sync_party` を付けない（付けるとフロントが `party_snapshot` 用の一括 `party` を早く反映する） |

`stat_check_each_ally` を追加する場合は、**失敗行ごと**に `sync_party` + `party` を付けること。最後の 1 行にまとめない。**直前の narration には `markLastLineSyncParty` を付けない**（deferred effect 用の処理を流用しない）。

フロントは `party_snapshot`（表示開始時）と行 `party`（各行 sync 時）を使い分ける。行 `party` を持つセグメントでは、`sync_party` のみの行で `party` トップレベルを一括反映しない。

## 8. テキスト・判定・SE

- 置換: `{target_name}`, `{chosen_name}`, `{name}`, `{success_rate}`, `{stat_check_label}`（例: 素早さ判定 / 筋力判定）
- ステータス判定の成功率: `min(95, ceil(能力値 × scaledMultiplier × (現在HP / 最大HP)))`（端数切り上げ）
- `scaledMultiplier = ceil(node.stat_multiplier × dungeon_floor_masters.stat_multiplier_scale / 100)`（最低 1）。2 層は scale=50 で 1 層の半分（切り上げ）
- `party_choice` で直後に `stat_check` がある場合: プロンプト先頭に判定名、各選択肢は `名前（成功率N%）`
- 地の文プレビュー（`dodge_preview` / `force_open` など）: `{stat_check_label}` と `{success_rate}` を併記
- `chance_branch` は CSV の `stat_multiplier` をそのまま成功率（%）として使用（HP 乗算なし、上限 95%）
- 判定ロール: `random_int(1, 100) <= 成功率`
- 判定直後の API: `segment.stat_check_result` が `"success"` または `"fail"`（フロントで `success` / `miss` SE）
- ストーリー送りタップ: SE なし（負荷対策のため廃止）
- ダンジョン「進む」: `se/cursor.mp3`
- BGM（BGM ON 時）: ホーム `bgm/home.mp3`、ダンジョン `bgm/dungeon.mp3`、通常戦闘 `bgm/battle.mp3`、ボス `bgm/boss_battle_2.mp3`
