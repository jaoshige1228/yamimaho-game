# ダンジョン探索

やみまほのダンジョン画面（`/dungeon`）の仕様です。ホーム画面からダンジョンに入り、「進む」で深さを進めながら戦闘または探索イベントが発生します。

**新規イベント追加:** 企画データの渡し方は [ダンジョンイベント企画テンプレ.md](./ダンジョンイベント企画テンプレ.md) を参照。

---

## 1. 概要

1. ホーム画面（`/hub`）で「ダンジョンに潜る」→ 層を選ぶページ（`/dungeon/enter`）→ `POST /api/dungeon/enter`
2. ダンジョン画面で「進む」→ `POST /api/dungeon/advance`
3. 応答に応じて戦闘画面へ遷移するか、探索イベント（セリフ・選択）を再生する
4. 探索イベント完了後、再び「進む」可能

---

### ダンジョン内の回復（2026-11-11 に作り直し）

ダンジョン画面の左下の「**＋ 回復**」ボタン（戦闘中・探索イベント中・ストーリー中は出ない／押せない。`canHeal`）で、回復画面（`DungeonHealModal.vue`）が下から開く。誰かの HP・MP が減っている（戦闘不能を含む）。
（以前はボタンの角に赤い点が付いたが、邪魔なので 2026-11-13 に消した。傷ついた味方の目印は出さない）

- **回復する相手をカードで選ぶ**: 4 人のカードに、顔・名前・HP/MP の数字とバー・「戦闘不能」の表示。開いたときは、いま一番必要としていそうな人が選ばれている（HP の割合がいちばん低い生存者 → 戦闘不能の人 → MP が減っている人 → 先頭）
- **使うものを選ぶ**: 「アイテム」「魔法」のタブ（件数つき）。アイテムは回復アイテム（HP/MP の薬・宇宙樹の葉）だけ、魔法は回復・蘇生の魔法だけ。各行に **選んだ相手に使ったときの結果**（`サフィリア　HP 35 → 85`、全体魔法は「傷ついた味方 N 人のHPを X ずつ回復」）が出る。**使えないものは理由が出る**（HPは満タンです／戦闘不能です／戦闘不能の味方にだけ使えます／MPが足りません（あと N）／傷ついた味方がいません など）
- **使ったあと**: カードの数字とバーが動き、カードの上に「+50」「復活」が浮かび、結果の文（「HP回復薬を使った。」「サフィリアのHPが 50 回復した」）が出る。画面の高さは固定で、結果の文が出ても上下にずれない。相手やタブを変えると、前の結果の文は消える。魔法を使うと MP が減るので、魔法の一覧は読み直す
- パネルは後ろの画面が透けない（以前は半透明で、後ろのパーティ欄の文字が重なって読めなかった）
- API: `GET /api/dungeon/heal/options` の各魔法に、画面に出す見込みとして **`amount`**（`heal_mag` は武器込みの実効魔力×倍率、`heal` は power。全回復・蘇生は null）と **`revive_percent`**（蘇生後の HP の割合。気配 50・雫 100。蘇生以外は null）を足した。`POST /api/dungeon/heal` は従来どおり（`message`・`party`・`items` を返す）

### 層

- ダンジョンは **1〜3 層**（`game.dungeon.max_floor`）
- 現状プレイ可能なのは **1〜3 層**（`game.dungeon.playable_floor` = 3。3 層の敵・ボス・背景／BGM は下の「3 層」参照）
- `user_dungeon_progress.floor` … 現在挑戦中の層
- `user_dungeon_progress.unlocked_floor` … 解放済みの最深層（ボス撃破で +1）
- `user_dungeon_progress.cleared_floor` … クリア済みの最深層（0 = 未クリア。ボス撃破でその層まで記録。最終層はクリアしても解放層が増えないため、これで判定する）
- 入場: `POST /api/dungeon/enter` に `{ "floor": N }` を指定（Hub では解放済み層ごとにボタン表示）
- 未解放の層・未実装の層へは **403**

### 深さ

- `user_dungeon_progress.step` が深さ（0 から開始、進むたびに +1）
- 各層の最深部（ボス）の深さは `game.dungeon.floors.{N}.boss_step`（1 層 **31**、2 層 **31**、3 層 **31**）
- 1 層の通常戦闘は深さ帯で出現敵が変わる（`encounter_bands`）。敵マスタは `enemy_masters.csv` の `floor` 列で層別
  - 深さ 1〜10: コーモリ（`bat`）1〜2 匹
  - 深さ 11〜14: コーモリ（`bat`）2〜3 匹
  - 深さ 15〜20: コーモリとヘビビ（`bat` / `snake`）合計 2〜3 匹
  - 深さ 21〜25: コーモリ・ヘビビ・ムシプリンス（`bat` / `snake` / `beetle`）合計 2〜3 匹
  - 深さ 26〜30: ヘビビとムシプリンス（`snake` / `beetle`）合計 2〜3 匹
  - 深さ 31: ボス イフリーヌ（`inu_moe`）1 匹
  - 帯の中の敵種は、1 匹ごとに等確率で抽選する
- 2 層は 1 層とは別の敵帯（`config/game.php` の `floors.2.encounter_bands`。帯に `weights`（敵コード => 重み）があれば、敵 1 匹ごとに重み付きで抽選）
  - 深さ 1〜10: ジャック（`jack`）1〜2 匹
  - 深さ 11〜20: ジャックと刈り取る奴（`jack` / `shinigami`）合計 2〜3 匹（中間ボスの深さ 20 を除く）
  - 深さ 21〜25: ジャック・刈り取る奴・ヘルナイト（`jack` / `shinigami` / `knight`）合計 2〜3 匹
  - 深さ 26〜30: 刈り取る奴とヘルナイト（`shinigami` / `knight`）合計 2〜3 匹
  - **ミミック（`mimic`）はどの帯にも約 3% のレア枠**（敵 1 匹ごとの重み 1 / 約 31）。経験値 1000・ゴールド 5000 だが、手番ごとに 50% で逃げる
  - 深さ **31** でボス（エルドラゴン＋邪教徒 2 体）
- 3 層の敵帯は上の「3 層」の表（1〜10 バニッシャー／11〜20 バニッシャー・クリーナー／21〜30 クリーナー・リーパー・クラッシャー。深さ **31** でボス＝ナビ・ゼロ・ナビ）
- 2 層 **深さ 20** では通常抽選をスキップし **中間ボスイベント**（`floor2_mid_boss`）を強制起動。敗北リセット後に再び深さ 20 へ来れば **再戦** する
- ボス深度に到達した「進む」は **必ずボス戦**（通常抽選なし）
- **リセット条件**
  - ダンジョン由来の戦闘で **敗北** したとき（`BattleOrchestrator`）
  - 管理画面で「ダンジョン探索リセット」をオンにして適用したとき
- 通常戦闘 **勝利** では深さは維持
- **ボス撃破** では深さを 0 にリセットし、次の層が解放される（`dungeon_floor_cleared` イベント）。**ダンジョンから退出**（`in_dungeon = false`）し、戦闘結果からホーム画面へ戻る。**パーティ全員の HP/MP を全回復**する（勝利時の EXP・レベルアップを反映した最大値。撤退・敗北時と同じ扱い）

## 3. 1 回の「進む」での抽選

定数は [`backend/config/game.php`](../backend/config/game.php) の `dungeon` 配列（CSV にはしない）。

| 定数 | 既定値 | 意味 |
|------|--------|------|
| `battle_encounter_rate` | 30 | 戦闘（敵出現）になる確率（%） |
| `exploration_event_rate` | 55 | 機械的探索イベント（判定・アイテム等）になる確率（%） |
| `dialogue_event_rate` | 10 | 会話のみ探索イベントになる確率（%） |
| `flavor_narrative_rate` | 5 | ただの描写（フレーバーテキスト）になる確率（%） |

- `skip_battle_encounters` が ON のユーザーは **戦闘なし**（ボス深度を除く）。その場合、戦闘分 30% は機械的探索イベントに振り替え、**機械イベント 85% / 会話 10% / 描写 5%**
- 管理画面の **会話のみイベント100%モード**（`force_dialogue_events`）が ON のときは、ボス深度を除き **常に会話のみイベント**（他の抽選は行わない）
- それ以外は `random_int(1, 100)` で戦闘・機械イベント・会話・描写のいずれかを決定
- 機械的探索イベントの種類は `dungeon_event_masters` の weight で抽選（1 層の weight 合計は **94**、会話テーブルとは別プール）
- 会話のみイベントの種類は `dungeon_dialogue_event_masters` の weight で抽選（当たり枠 10% の中での比率）

> **要調整:** 2026-06 時点で 1 層イベント weight 合計は **132**（新規 4 件は仮値 `8` ずつ）。`dungeon_events.csv` の weight のみ変更すれば抽選比率を調整できます。

## 4. 戦闘エンカウント

- 敵マスタ: [`enemy_masters.csv`](../backend/database/csv/enemy_masters.csv)（`floor` 列で層別）
- 出現組み合わせ: `config/game.php` の `dungeon.floors.{N}.encounter_bands` と `boss_enemy_codes`（`DungeonStepEncounterBuilder`。同じコードを並べると複数体になり、同じ敵が複数いるときだけ名前に A・B が付く）
- ボス深度では `boss_step` の「進む」で必ずボス戦（通常の 30% 抽選は行わない）
- 戦闘メタ: `source=dungeon`, `floor`, `step`, `boss`, `can_flee`
- **逃げる**（ダンジョン戦闘・ボス以外）: `POST /battles/{id}/actions` に `action=flee`。100% 成功し深さを 1 減らす（最低 1）。戦闘状態は `fled`
- **撤退する**（ダンジョン画面）: `POST /dungeon/retreat`。所持金を `ceil(所持金 × 0.9)` にし、探索セッションを破棄してホーム画面へ。層・深さは維持。**パーティ全員の HP/MP を最大まで回復**

### 所持金

- `users.gold`（パーティ共有）。初期値 0
- hub / dungeon の HUD（左上 DAY・右上 所持金）で表示
- API: `GET /player/party` および `GET /dungeon` の `gold` フィールド

## 4.5 ただの描写（flavor）

「進む」で **10%** の確率で発生。探索セッションは作らず、`POST /api/dungeon/advance` の応答で `event: "flavor"` と `segment.kind: "story"` を返します。

- フロントは `StorySequencePlayer` で表示し、終了後そのまま「進む」可能
- パーティ状態・所持品・ゴールドへの影響なし
- 文言は [`DungeonFlavorNarrativeService.php`](../backend/app/Services/Dungeon/DungeonFlavorNarrativeService.php) の3パターンからランダム

---

### セッション

- テーブル: `dungeon_exploration_sessions`
- 進行中は `advance` を **409** で拒否
- 完了時にセッション削除・パーティ HP を API で返却

### segment の種類

| kind | クライアント動作 |
|------|------------------|
| `story` | `StorySequencePlayer` で `lines` をタップ送り（`sync_party` 行でゲージ更新）→ `POST /dungeon/exploration/continue` |
| `choice` | 生存メンバー選択（`lines` があれば先にストーリー再生）→ `POST /dungeon/exploration/choose` |
| `complete` | 終了。パーティ再表示、「進む」復帰 |

イベント終了直前に、エンジンが固定の締め描写 **「一行は先に進むことにした」**（地の文）を必ず 1 行挿入します（CSV 不要）。[`dungeon_dialogue_events.csv`](../backend/database/csv/dungeon_dialogue_events.csv) の会話のみイベントでは常に省略します。

### API

| メソッド | パス | ボディ |
|----------|------|--------|
| GET | `/api/dungeon` | —（`step` のみ） |
| POST | `/api/dungeon/enter` | — |
| POST | `/api/dungeon/advance` | — |
| POST | `/api/dungeon/exploration/continue` | `{ "session_id": "uuid" }` |
| POST | `/api/dungeon/exploration/choose` | `{ "session_id", "slot_id" }` |

### 実装クラス（バックエンド）

- `DungeonEventCatalog` … イベント・ノード取得
- `DungeonExplorationEngine` … ノード実行・判定・ダメージ
- `DungeonExplorationService` … start / continue / choose
- `PartyExplorationDamageService` … スロット指定ダメージ

#### HP/MP 表示タイミング（必読・実装規約）

| 原則 | 内容 |
|------|------|
| DB と UI の分離 | **DB への反映は早くてよい**（セグメント生成時にコミット）。**フッター HP の更新は描写と同時** |
| `sync_party` | プレイヤーに「効果が起きた」と見せる行に付ける。`StorySequencePlayer` がその行表示時に `sync-party` を emit |
| `party_snapshot` | 効果適用前のパーティ。初回表示用 |
| `party`（API ルート） | セグメント内の全効果適用後の最終パーティ |
| `party`（行メタ） | **複数人へ順次ダメージ/回復**（`stat_check_each_ally` 等）では、各行の `party` に**その時点までの累積結果**を載せ、`sync_party` とセットで送る |

**グラフ設計:** 「結果の地の文／セリフ → 効果ノード → 次の描写」の順。効果ノード直前の表示行に `sync_party`（deferred 系はエンジンが自動付与）。**ダメージ／ゴールドの数値は地の文（`narration`）に書く。** `{damage_amount}` / `{gold_amount}` は、次の効果ノードまでセリフ・地の文だけが続くなら先読み（最大 8 ノード）で展開される。直前の地の文に数値が無いときは、エンジンが直近の地の文へ追記する（セリフには付けない）。**金額入りの地の文は効果ノードの「前」に置くこと**（後ろに置くと追記と重なって二重表示になる）。

**既存イベント監査（2026-06）:**

| イベント | 判定 |
|----------|------|
| trap_arrow 失敗 | OK（`fail_narr` 表示時に sync） |
| suspicious_spring ハズレ | OK（「マズイ」セリフ表示時に sync） |
| treasure_chest / trapped_chest 報酬 | OK（報酬地の文の直前で sync） |
| man_eating_plant 失敗ダメージ | OK（地の文 `fail_swallow` に `{damage_amount}`。直後の叫びセリフには付けない） |
| suspicious_spring 毒見失敗 | OK（反応セリフ → 地の文 `{damage_amount}` → `apply_damage_chosen`） |
| trapped_chest 爆発 | OK（全員同時ダメージ → `boom` 1 回 sync で正しい） |
| flash_flood 精神判定 | **修正済** — 失敗行ごとに sync + `party`。直前の「水に飲まれた」行に `sync_party` を付けない（付けるとフロントが `party_snapshot` 用の一括 `party` を早く反映する） |

`stat_check_each_ally` を追加する場合は、**失敗行ごと**に `sync_party` + `party` を付けること。最後の 1 行にまとめない。**直前の narration には `markLastLineSyncParty` を付けない**（deferred effect 用の処理を流用しない）。

フロントは `party_snapshot`（表示開始時）と行 `party`（各行 sync 時）を使い分ける。行 `party` を持つセグメントでは、`sync_party` のみの行で `party` トップレベルを一括反映しない。

## 8. テキスト・判定・SE

- 置換: `{target_name}`, `{chosen_name}`, `{name}`, `{PC1}`〜`{PC4}`（パーティスロットのファーストネーム）, `{PC1のファミリーネーム}`〜`{PC4のファミリーネーム}`（`second_name`）, `{success_rate}`, `{stat_check_label}`（例: 素早さ判定 / 筋力判定）, `{item:アイテムコード}`（その層で出すアイテムの名前。報酬アイテムの差し替え `reward_item_map` 適用後）
- ステータス判定の成功率: `min(95, ceil(能力値 × scaledMultiplier × (現在HP / 最大HP)))`（端数切り上げ）
- `scaledMultiplier = ceil(node.stat_multiplier × dungeon_floor_masters.stat_multiplier_scale / 100)`（最低 1）。2 層は scale=50 で 1 層の半分（切り上げ）。ただし下の「層ごとの数値の上書き」で倍率を指定したノードは、その値そのものを使う（層補正はかけない）
- **層ごとの数値の上書き**（`dungeon_event_floor_overrides.csv`、列は `floor,event_code,node_key,stat_multiplier,fixed_damage`）
  - ノード CSV は全層で共有なので、特定の層だけ成功率・ダメージ・ゴールドを変えたいときは 1 行足す。空のセルは「上書きしない」（例: `apply_damage` の `stat_multiplier`＝HP 下限を残したままダメージだけ変えられる）
  - `stat_multiplier` を入れられるのは `stat_check` / `stat_check_each_ally`（その層で使う倍率そのもの。**小数可**、成功率は切り上げ）、`grant_gold`（ゴールド額）、`chance_branch`（成功率 %）。`fixed_damage` を入れられるのは `apply_damage` / `apply_damage_chosen` / `apply_damage_party` / `stat_check_each_ally`
  - 実行時に CSV を直接読んで `DungeonEventCatalog::findNode`（層を渡す）がメモリ上のノードに反映する。**DB のノード行は書き換えない**ので `db:seed` は要らない（CSV を保存すれば次の探索から効く）。`{damage_amount}` / `{gold_amount}` の先読み・選択肢の成功率表示も上書き後の値になる
  - 行の `floor` / `event_code` / `node_key` が実在しない・値を入れられないノードを指すと `DungeonEventFloorOverridesTest` が失敗する（タイプミス検知）
- `party_choice` で直後に `stat_check` がある場合: プロンプト先頭に判定名、各選択肢は `名前（成功率N%）`
- 地の文プレビュー（`dodge_preview` / `force_open` など）: `{stat_check_label}` と `{success_rate}` を併記
- `chance_branch` は CSV の `stat_multiplier` をそのまま成功率（%）として使用（HP 乗算なし、上限 95%）
- 判定直後の API: `segment.stat_check_result` が `"success"` または `"fail"`。成功・失敗の SE（`success` / `miss`）は、**ダイスロールのログ（下の `dice`）が付いた行を表示したとき**に `StorySequencePlayer.vue` が鳴らす（`stat_check_result` のセグメントにログ付きの行があれば `DungeonView.vue` のセグメント単位の SE は鳴らさない＝二重に鳴らない）。ログ付きの行が無いセグメント（戦闘など）だけ、従来どおり `DungeonView.vue` が鳴らす
- **ダイスロールのログ**（2026-11-10）: 成功・失敗が判明したとき（= 上の SE が鳴るとき）、そのとき表示されるテキストの **1 行目**に `1d100<=成功率 ＞ 出目 ＞ 成功`（失敗なら `失敗`）を必ず出す。成功は薄い青（`#9fcdff`）、失敗は薄い赤（`#ff9d9d`）で、**細字（`font-weight: 300`）・不透明度 0.9**（本文より控えめに見せる。`story-window.css` の `.story-text-window__dice`）で、**出目だけ太字**（`font-weight: 700`。`1d100<=55 ＞ 70 ＞ 失敗` の `70`。`StoryTextWindow.vue` が `text` を ` ＞ ` で 3 つに分けて、真ん中を `.story-text-window__dice-roll` にする。形が違うときは分けずそのまま出す）。例: 成功率 55%・出目 70 → `1d100<=55 ＞ 70 ＞ 失敗`、成功率 20%・出目 1 → `1d100<=20 ＞ 1 ＞ 成功`。出目が成功率ちょうどは成功（`<=`）。成功率は上限 95% に丸めたあとの値（実際に比べた値）
  - API: 結果の segment の **最初に表示される文**（`lines` のうち、文が空でなく、暗転だけの行でない最初の行）に `dice: { text, result: 'success'|'fail', rate, roll }` が付く（文 `text` 自体は変えない）。表示される文が 1 つもなければ、ログだけの行を作る。`DungeonExplorationEngine::segmentWithStatCheckResult` / `rollD100` / `diceLog`
  - `stat_check_each_ally`（鉄砲水）は `stat_check_result` を持たないが、**1 人ずつの結果の行**（成功の行・失敗の行）にそれぞれ `dice` が付き（挑戦の行には付かない）、その行を表示するたびに成功・失敗の SE が 1 回ずつ鳴る（4 人なら 4 回）
  - 画面: `StoryTextWindow.vue` が本文の先頭に文字送りなしで出す（地の文は 1 行目、セリフは話者名の下・「 の前）。`StorySequencePlayer.vue` が行の `dice` を渡す
  - 見えない抽選（`chance_branch`。宝箱の中身・スフィンクスの出題など）は、プレイヤーに成功・失敗を知らせず SE も鳴らさないので、ログも出さない
  - 判定の直後に表示される文がないイベントを足すとログの出す場所がなくなるので、`DungeonExplorationDiceLogTest` が全イベントのグラフを調べて見張っている（判定の成功・失敗の先が、地の文かセリフであること）
- ストーリー送りタップ: SE なし（負荷対策のため廃止）
- ダンジョン「進む」: `se/cursor.mp3`
- BGM（BGM ON 時）: ホーム `bgm/home.mp3`、通常戦闘 `bgm/battle.mp3`、ボス `bgm/boss_battle_2.mp3`、中間ボス `bgm/broken.mp3`、**空間の裂け目のボス戦 `bgm/last_boss.mp3`**（2026-11-14 から。戦闘の `meta.bgm = 'last_boss'` で指定。どの層から入っても同じ。探索イベントの裂け目もテスト戦闘の `rift_boss` も同じ。`dungeonTheme.js` の `battleBgmTrack` が `meta.bgm` の `broken` / `last_boss` を層より優先して選ぶ）
- **探索画面の背景とBGMは層ごとに違う**（対応表は `frontend/src/utils/dungeonTheme.js`。表にない層は 1 層と同じ）

  | 層 | 背景（`assets/bg/`） | 探索BGM（`assets/audio/bgm/`） |
  |----|----------------------|--------------------------------|
  | 1 層 | `dungeon1.webp` | `Dim2.mp3` |
  | 2 層 | `2nd_floor.webp` | `dungeon.mp3` |

  いま探索している層は `GET /api/player/navigation` の `dungeon_floor` で渡す（ルーターが画面遷移のたびに取得するので、探索画面を開く時点で層が分かっている）。層を増やすときは `dungeonTheme.js` の 2 つの表と、`useBattleAudio.js` の `BGM_TRACKS` に足す

## 9. 管理画面（/admin）

> **テストモード（`/admins` 管理画面・`/test_battles` テスト戦闘とその API）の公開／非公開**
> リリース前なので、本番（`APP_ENV=production`）でも使える。切り替えは [`config/game.php`](../backend/config/game.php) の `test_mode_enabled`（環境変数 **`GAME_TEST_MODE`**、既定 `true`）。**リリースするときは本番の `.env`（`infra/terraform/templates/app.env.tpl` → 生成される `app.env`）に `GAME_TEST_MODE=false` を入れる**と、`/api/admins/*` と `/api/test_battles/*` が本番を含めて 404 になる（`EnsureTestModeEnabled` ミドルウェア）。ホーム画面の開発用リンク（`/admins` `/test_battles`）はフロントでは隠れないので、閉じるときはあわせて外す。

`POST /api/admins/dungeon-settings`

```json
{
  "skip_battles": true,
  "force_dialogue_events": false,
  "reset_progress": false
}
```

| フラグ | 動作 |
|--------|------|
| skip_battles | デモユーザーの `skip_battle_encounters` を永続更新 |
| force_dialogue_events | デモユーザーの `force_dialogue_events` を永続更新。「進む」抽選で会話のみイベントが **100%**（ボス深度を除く） |
| reset_progress | **このリクエスト時のみ** `step = 0` にリセット |

`GET /api/admins/dungeon-settings` で現在のフラグと層・深さ・解放層（`unlocked_floor`）・クリア済み層（`cleared_floor`）を取得できます。

### ダンジョンのクリア状況

`POST /api/admins/dungeon-clear`

```json
{ "floor": 3 }
```

指定した層（1〜`max_floor`）をクリア済みにします。`cleared_floor` をその層まで上げ、次の層（最終層なら最終層まで）を解放します（`DungeonProgressService::markFloorCleared`。ボス撃破時と同じ記録処理）。

- **元に戻せません**。`cleared_floor` を下げる機能はなく、すでにクリア済みの層を指定しても変わりません（メッセージは「すでにクリア済みです」）
- 浅い層もまとめてクリア済みになります（3層を指定 → 1・2・3層がクリア済み）
- 探索中の層・深さ・パーティの HP/MP は変えません
- 画面（/admins）では、1〜3層それぞれに「クリア済みにする」ボタン（確認あり）を出します
- ホームの「記録をリセット」では、`cleared_floor` も 0 に戻ります

### ゴールドの追加

管理画面の「ゴールド追加」で、パーティーの所持金に**指定した数のゴールドを足せる**（上書きではなく加算）。いまの所持金も画面に出る。

| API | 内容 |
|-----|------|
| `POST /api/admins/grant-gold` | `{ "gold": 1000 }`。1〜9,999,999 の整数。レスポンスは `message` と、足したあとの `gold` |
| `GET /api/admins/party` | レスポンスに現在の所持金 `gold` が入る |

- 範囲外・整数でない・未指定は 422（所持金は変わらない）。合計は `users.gold` の上限（約42.9億）を超えないよう丸める
- 他の管理画面と同じく、テストモード（`GAME_TEST_MODE`）を閉じると 404

### 味方の装備の操作

管理画面の「装備の操作」で、味方の武器・防具を、**持っているかどうかに関係なく**好きなものに替えられる（キャラごとに武器・防具を選び、「装備を変更」で反映）。

| API | 内容 |
|-----|------|
| `GET /api/admins/equipment` | 選べる武器・防具（全マスター。補正の小さい順）と、いまの味方の装備（`weapon_code` / `armor_code`） |
| `POST /api/admins/equipment` | `{ "slot_id": "pc1", "weapon_code": "staff_master", "armor_code": "robe_master" }`。武器・防具はどちらか片方だけでもよい（送らなかった側は今のまま） |

- 替えた装備は**そのキャラの所持扱い**になる（プレイヤーの装備画面でも選べる／外したあとに付け直せる）
- **装備なしにはできない**（`null` だけの指定は 422）。装備なしのキャラは、パーティ取得（`ensureParty`）のたびに初期装備（基本の杖・基本のローブ）へ戻されるため。いちばん弱くしたいときは基本の杖・基本のローブを選ぶ
- 武器・防具マスター（`weapon_masters.csv` / `armor_masters.csv`）を増やすと、一覧にも自動で載る
- 他の管理画面と同じく、テストモード（`GAME_TEST_MODE`）を閉じると 404
